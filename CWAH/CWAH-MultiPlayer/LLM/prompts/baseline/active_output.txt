## Output Requirements

Output one available action and its associated <subtask_id>. Use an active public task ID for task-specific actions, or null for task-independent exploration or communication. Grab/put actions must match the selected task's object and destination.

For physical actions, leave <message> empty. For [send_message], provide a concise message. Keep all output fields at the top level; do not put control tags inside <cot> or <message>. Use the exact physical action text, including its object IDs and parameters, from the available list.

Choose [wait] when there is no useful action or subtask to pursue this step. It consumes one environment step without moving or messaging. For [wait], use <subtask_id>null</subtask_id> and leave <message> empty.

<action>Exactly one available physical action.</action>
<subtask_id>Active task ID or null.</subtask_id>

<action>[send_message]</action>
